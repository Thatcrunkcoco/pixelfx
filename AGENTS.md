# AGENTS.md

pixelfx: code-driven pixel art effects (`src/fx/`), the core it draws with (`src/core/`), a
gallery, and the Node tools in `tools/` that render, inspect, act out, compare and check
effects. `docs/AUTHORING.md` is the reference for writing an effect; `skills/pixelfx/SKILL.md`
is the workflow.

## Commands

- `node tools/render.mjs <id> [--sheet] [--gif] [--mp4] [--opts '{...}']` — frames/contact
  sheet into `records/<category>/<name>/`
- `node tools/inspect.mjs <id> [--zoom=N] [--mp4]` — every frame at 1x and zoomed, plus
  per-frame change values
- `node tools/act.mjs <id>` — consecutive 12 fps steps of a character act
- `node tools/compare.mjs`, `node tools/montage.mjs`, `node tools/sheets.mjs` — comparisons
- `node tools/check.mjs <id>` — geometry, loop seams, seeding, speed, act-key checks
- `node tools/preview.mjs [--no-open]` — builds `pixelfx-preview.html` from `src/`
- `node tools/list.mjs <words>`, `node tools/new.mjs <category>/<name> [--loop]`
- `npm run check`, `npm run render`, `npm run preview`, `npm run gallery`

No bundler step for the library: `src/` is ESM consumed directly; only the gallery preview
inlines it with esbuild.

## Images are a budget, not a scratchpad

OpenCode re-sends every image in a session on every request, and any provider that caps
images per request (opencode-go 30, Mistral 20, Azure/Anthropic 50) turns the session
permanently useless at `Too many images in request: N > cap` — `/compact` fails the same way.
This project's loop is render → look → fix, so it accumulates images faster than anything
else. Treat 20 images in history as the hard ceiling.

- Look at what the task needs, once each. `inspect.mjs` writes several PNGs (`strip-1x`,
  `strip-zoom`, `clear`, `timing`) — read the one that answers the question, not all of them.
- When the direction is open, render the drafts, build **one** montage for the batch and look
  at that, instead of reading one sheet per draft.
- Prefer text verdicts first: `check.mjs`, the per-frame change table from `inspect.mjs`, and
  pixel diffs say whether something is wrong without an image. Look at the render when the
  numbers are ambiguous or the fix is visual.
- Re-look by overwriting the same render (`records/<id>/…`) rather than writing new files per
  round; never keep one frame per iteration in history.
- Delete superseded drafts as the skill says; don't re-read files you've already judged.
- If a request dies with an image-count error, say so plainly and compact or drop image turns
  before continuing — don't retry the same request.

## Conventions

- Effects live one per file in `src/fx/<category>/<name>.js`; new files come from
  `tools/new.mjs`, and exported metadata/`act` follow `docs/AUTHORING.md`.
- Keep changes consistent with the surrounding files; don't edit `pixelfx-preview.html` by
  hand (generated by `tools/preview.mjs`).
- Reject unseeded randomness, loops that don't close and one-shots that don't end empty;
  `check.mjs` enforces these.
- Leave unrelated working-tree changes alone.
